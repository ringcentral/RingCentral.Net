# Domain docs

This repo uses a single context: root GLOSSARY.md and docs/adr/.

Before exploring code:
- Read GLOSSARY.md when present.
- Read ADRs relevant to the area being changed.

Proceed silently when these documents are absent. Create them
lazily through domain modeling when terms or decisions warrant it.

Use the glossary's canonical terms in code, tests, and tickets.
Surface conflicts with existing ADRs before proposing changes.
